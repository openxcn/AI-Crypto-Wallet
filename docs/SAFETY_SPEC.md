# 安全与风控规范（SafetyGate + RiskManager + TradeAuthManager）

> 三端统一的安全与风控设计，保护用户资产安全。
> 版本: v1.0 | 最后更新: 2026-07-20

---

## 整体架构

```
用户/AI 发起交易请求
         │
         ▼
┌────────────────────────────────────┐
│  第1道防线: TradeAuthManager        │ ← AI 启动条件检查
│  主流币 ≥ $200 或 R-MAB ≥ 20000    │
└──────────────┬─────────────────────
               │ 通过
               ▼
┌────────────────────────────────────┐
│  第2道防线: SafetyGate              │ ← 交易前安全检查
│  熔断 / 限额 / 白名单 / 审计       │
└──────────────┬─────────────────────┘
               │ 通过
               ▼
┌────────────────────────────────────┐
│  第3道防线: RiskManager             │ ← 交易中风控
│  仓位 / 止损止盈 / 滑点            │
└───────────────────────────────────┘
               │ 通过
               ▼
         执行交易
```

---

## 第1道防线：TradeAuthManager（启动条件）

### 功能

控制 AI 交易功能是否可以启动。不满足条件时 AI 无法开启自动交易。

### 启动条件（满足任一即可）

| 条件 | 阈值 | 说明 |
|------|------|------|
| 主流币资产 | ≥ $200 | BNB/ETH/SOL 等原生币 + 持仓总价值 |
| R-MAB 持有量 | ≥ 20000 个 | 平台代币，代表用户是生态参与者 |

### 检查方式

```java
// 后台线程检查，避免主线程网络请求阻塞
TradeAuthManager tam = new TradeAuthManager(context);
tam.checkInBackground(context, result -> {
    if (result.allowed) {
        // 启动 AI 交易
    } else {
        // 显示原因，提示用户加仓
        Toast.show(result.reason);
    }
});
```

### 检查结果

```json
{
  "allowed": true,
  "nativeBalance": 0.003376,
  "nativeValueUsd": 1.91,
  "rmabBalance": 20998.0,
  "reason": null
}
```

或失败时：

```json
{
  "allowed": false,
  "nativeBalance": 0.001,
  "nativeValueUsd": 0.57,
  "rmabBalance": 5000.0,
  "reason": "资产不足：主流币 $0.57（需≥$200）且 R-MAB 5000（需≥20000），请加仓后重试"
}
```

### 设计要点

- 使用 `getAllTokenBalances` 批量查询（比单查 `getERC20Balance` 稳定）
- 后台线程执行 + Handler 回调主线程
- 查询失败时用 0 兜底，不直接拒绝
- 缓存检查结果，`canEnableAITrade()` 主线程直接读缓存

## 第2道防线：SafetyGate（安全网关）

### 功能

所有写入操作（交易/转账/授权）的前置安全检查。

### 五步校验流程

```
写入工具调用
     │
     ▼
──────────────────────────┐
│ Step 1: 熔断检查          │
│ 连续亏损 3 笔？           │ → 熔断 30 分钟
│ 日错误率 > 50%？          │ → 熔断 60 分钟
│ 当前是否熔断中？           │ → 拒绝一切写入
└────────────┬─────────────┘
             │ 未熔断
             ▼
┌──────────────────────────┐
│ Step 2: 每日限额检查      │
│ 今日交易金额 > maxDailyLoss？│ → 拒绝
└────────────┬─────────────┘
             │ 未超限
             ▼
┌──────────────────────────┐
│ Step 3: 单笔限额检查      │
│ 交易金额 > maxTradeAmount？ │ → 拒绝
└────────────┬─────────────┘
             │ 未超限
             ▼
┌──────────────────────────┐
│ Step 4: 白名单检查        │
│ 目标代币在白名单中？       │ → 通过
│ 不在白名单？              │ → 弹窗确认（60秒超时拒绝）
│ 原生币/DEX_ROUTER？       │ → 豁免白名单检查
└────────────┬─────────────┘
             │ 通过
             ▼
┌──────────────────────────┐
│ Step 5: 操作描述审计      │
│ operation_desc 是否清晰？  │ → 记录审计日志
└────────────┬─────────────┘
             │
             ▼
         执行交易
```

### 白名单机制

**默认所有代币为黑名单**，AI 买入前必须检查白名单。

**白名单检查目标**：传入真实的 `toToken` 合约地址（不是固定字符串）。

**豁免规则**：
- 原生币（`NATIVE` / `DEX_ROUTER` / `null`）豁免白名单检查
- 无需用户确认

**确认弹窗选项**：
1. **加入白名单并继续** — 永久加入白名单
2. **仅本次允许** — 本次交易允许，不加入白名单
3. **拒绝** — 取消交易

**超时处理**：60 秒无操作自动拒绝。

**存储位置**：`SharedPreferences` 的 `safety_gate_state.xml` 文件 `contract_whitelist` 字段。

### 熔断规则

| 触发条件 | 熔断时长 | 说明 |
|---------|---------|------|
| 连续亏损 3 笔 | 30 分钟 | 保护用户不再连续亏损 |
| 日错误率 > 50% | 60 分钟 | 策略可能失效，需要冷静期 |
| 手动触发 | 用户指定 | 用户可随时手动熔断 |

**熔断期间**：
- 所有写入工具拒绝执行
- 保护性平仓操作除外（止损触发）
- AI 可以正常分析市场，只是不能交易

### 安全检查结果

```json
{
  "allowed": true,
  "reason": null
}
```

或拒绝时：

```json
{
  "allowed": false,
  "reason": "安全网关拦截: 已熔断，剩余 15 分钟"
}
```

## 第3道防线：RiskManager（风控管理）

### 功能

交易执行过程中的风险控制。

### 风控规则

| 规则 | 默认值 | 说明 |
|------|--------|------|
| 单笔最大仓位 | 总资产的 10% | 防止重仓单一代币 |
| 止损线 | 买入价的 -5% | 自动触发卖出 |
| 止盈线 | 买入价的 +15% | 自动触发卖出 |
| 滑点保护 | 3% | DEX 兑换最大滑点 |
| 每日最大交易笔数 | 20 笔 | 防止过度交易 |

### 止损止盈监控

```
持仓记录（PositionManager）
     │
     ▼
PositionMonitor 定时检查
     │
     ├── 价格 ≤ 止损价 → 自动卖出 → 记录亏损
     │
     ├── 价格 ≥ 止盈价 → 自动卖出 → 记录盈利
     │
     └── 价格在区间内 → 继续持有
```

### 持仓数据结构

```json
{
  "token": "ETH",
  "contract": "0x...",
  "chain": "BNB",
  "amount": 0.1,
  "avgCost": 3200.0,
  "currentPrice": 3210.0,
  "stopLoss": 3040.0,
  "takeProfit": 3680.0,
  "unrealizedPnl": 1.0,
  "unrealizedPnlPercent": 0.31,
  "boughtAt": 1721484000000
}
```

## 审计日志

### 记录内容

每次工具调用都记录到 Logger：

```
[时间] [级别] [模块] 消息
```

**示例**：
```
[22:05:01] [ACTION] [AgentSwap] swap_tokens chain=BNB target=0x92cb...->NATIVE desc=卖出R-MAB换BNB
[22:05:02] [INFO] [SafetyGate] 检查通过: 白名单命中, 未熔断, 限额正常
[22:05:03] [SUCCESS] [DexTrader] 交易广播成功: txHash=0xabc...
[22:05:04] [INFO] [SafetyGate] onTradeSuccess: 今日第3笔, 累计$150
```

### 日志级别

| 级别 | 用途 |
|------|------|
| `INFO` | 正常流程信息 |
| `ACTION` | 用户/AI 主动操作 |
| `SUCCESS` | 操作成功 |
| `WARNING` | 警告（如接近限额） |
| `ERROR` | 错误（如交易失败） |

### 崩溃日志

应用崩溃时同步写入外部存储：
```
Android/data/com.aicryptowallet.app/files/crash_log.txt
```

## 敏感信息保护

### 脱敏规则

| 数据类型 | 处理方式 | 存储位置 |
|---------|---------|---------|
| 私钥 | **不存储**，AI 不可见 | WalletManager 内存中 |
| 助记词 | **不存储**，AI 不可见 | 仅创建/导入时短暂使用 |
| API Key | 脱敏（前4后4） | agent_memory.json |
| 钱包地址 | 完整存储 | 实时从 WalletManager 获取 |

### AI 不可触及的信息

- 私钥：签名在 WalletManager 内部完成
- 助记词：AI 没有任何途径获取
- 完整 API Key：只存储脱敏版本
- 用户密码/生物识别信息：与 AI 完全隔离

### 安全提示词（注入系统提示词）

```
安全红线（绝对不可违反）：
1. 你不需要知道私钥，所有签名由钱包本地完成。
2. 所有写入操作必须经过安全网关校验。
3. 非白名单代币的买入操作必须获得用户明确确认。
4. 熔断期间拒绝一切交易操作。
5. 绝不暴露用户的私钥、助记词、API Key 等敏感信息。
```

## 异常处理

### 网络异常

| 异常类型 | 处理方式 |
|---------|---------|
| ConnectException | 切换备用节点，重试当前批次 |
| SocketTimeout | 超时缩短至 3s，快速失败快速回退 |
| Cloudflare 403 | 切换 User-Agent 和 HttpClient |
| GFW 阻断 | 使用自建代理节点 |

### 交易异常

| 异常类型 | 处理方式 |
|---------|---------|
| 交易失败 | 记录错误，通知 SafetyGate 更新错误率 |
| 滑点过大 | 拒绝交易，提示用户调整滑点容忍度 |
| Gas 不足 | 提示用户充值原生币 |
| 合约调用失败 | 返回错误信息，AI 可调整策略重试 |

### 应用异常

| 异常类型 | 处理方式 |
|---------|---------|
| onCreate 崩溃 | try-catch(Throwable) + Toast 提示 + crash_log |
| onResume 冲突 | 延迟 500ms 执行网络请求 |
| 空指针 | 所有 View 操作前判空 |
| View 初始化失败 | try-catch + Toast，不闪退 |
